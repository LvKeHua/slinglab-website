## 一、项目概览

在现有 **筹码筛选** (https://app.slinglab.xyz/screener/) 基础上，新增 **小币筛选** Tab，基于 @derrrrrrrq 的完整5步筛选方法论（扫描→排除→确认→入场→心法），从 Binance 合约数据中自动识别处于吸筹/拉升早期的币种，并标注风险信号。

与现有妖币扫描器的区别：
- 妖币扫描器 = 只看 vol/OI 比（挤压信号）
- **小币筛选系统 = 5步完整筛选流程**，包含OI阶段判断、排除清单、确认信号、入场时机

### 最终架构

```
GitHub Actions (US IP, 每5分钟)
  │
  ├─ relay.mjs ─→ Binance fAPI → 24h ticker + OI + funding rate + depth
  │                ├─ /api/relay-tickers       (筹码数据)
  │                ├─ /api/relay-demon         (妖币数据)
  │                └─ /api/relay-coinfilter    (小币筛选数据) ← 新增
  │
  ▼
Cloudflare Worker v9 (tokenomics-screener)
  │
  ├─ KV 存储 (TOKENOMICS_MARKET_DATA)
  │   ├─ market_data           → 711 coins (Binance/Bybit/OKX)
  │   ├─ demon_data             → 299 coins (Binance OI)
  │   ├─ coinfilter_data        → 299 coins + 信号标签   ← 新增
  │   ├─ coinfilter_updated     → 时间戳                  ← 新增
  │   ├─ oi_history:{symbol}    → 最近7天OI快照            ← 新增
  │   └─ dashboard_html         → 前端页面 (≈80KB)
  │
  ├─ GET /api/tickers        → 筹码筛选数据
  ├─ GET /api/demon          → 妖币扫描数据
  ├─ GET /api/coinfilter     → 小币筛选数据               ← 新增
  ├─ GET /api/status         → 状态汇总（扩展coinfilter字段）
  └─ GET /                   → 前端 HTML
```

### 现有数据（从妖币扫描器继承）

| 字段 | 来源 | 说明 |

| volume_oi_ratio | 计算 | 成交额/OI |
| amplitude_pct | 24h ticker | 24h振幅 |
| trade_count | 24h ticker | 24h成交笔数 |

### 新增数据（小币筛选器需要）

| 字段 | 来源 | 说明 | Binance API 端点 |
|------|------|------|-----------------|
| funding_rate | /fapi/v1/fundingRate | 最近一期资费率 | 每5分钟1次，299币 |
| orderbook_depth | /fapi/v1/depth?limit=20 | 前20档累计深度(USDT) | 每5分钟1次，权重5/请求 |
| listing_date | Binance /api/v3/exchangeInfo | 合约上线日期 | 静态数据，首次获取后缓存 |
| oi_history | KV oi_history:{symbol} | 最近7天OI快照（方案A） | relay每次抓取时存入 |

### OI 阶段判断方案

**不使用OI增长率。** 原文从未提及"OI增长率"这个概念，他只说"OI从低位开始增长"（定性）和"2M-8M OI的时候"（绝对值区间）。

改用 **OI绝对值区间** 判断阶段：

| OI 区间 | 阶段 | 标签 | 原文依据 |
|---------|------|------|---------|
| 0 - 2M USDT | 蓄水期 | ⏳ 等待 | "还在蓄水" |
| 2M - 8M USDT | 早期 | 💎 小币候选 | "2M-8M OI的时候，我基本上OI持仓都是在2%左右" |
| 8M - 30M USDT | 拉升期 | 🚀 拉升早期 | "在拉升的早期是oi增多，价格上涨，最舒服最顺畅也是风险最低的" |
| 30M - 80M USDT | 中期 | ⚡ 中期 | 推算（无精确原文） |
| 80M+ USDT | 大后期 | ⛔ 大后期派发 | "oi维持在高位，但是交易量萎靡" + "100M的单向oi你可以忽略不及，百分之90以上都是噪音" |

**7天预热期后**，可以用KV中存储的OI历史做趋势确认（OI是持续增长还是持续下降），但**不计算百分比增长率**。

## 九、数据可行性分析

### Binance API 请求量估算

| 数据 | 请求/币 | 299币总请求 | 权重 | 说明 |
|------|---------|-------------|------|------|
| 24h ticker | 1 | 299 | 2 | 现有 |
| OI | 1 | 299 | 1 | 现有 |
| fundingRate | 1 | 299 | 1 | **新增** |
| depth(20) | 1 | 299 | 5 | **新增** |
| exchangeInfo | 1 | 1 | 1 | 静态，首次缓存 |

**总请求权重**：299×2 + 299×1 + 299×1 + 299×5 + 1 = 299×9 + 1 ≈ 2692 权重/5分钟
**Binance限流**：2400权重/分钟 → 每5分钟可承受12000权重
**结论**：✅ 可行，需要20线程并发，约67秒完成

### OI 历史数据

**方案**：relay 每次抓取时存入 KV `oi_history:{symbol}`，格式 `[{"date":"2026-08-02","oi":32500000},...]`
- 存储7天快照，每天1条，每个symbol约200字节
- 299币 × 200字节 ≈ 60KB，KV 免费额度内
- 7天后自动切换到精确OI趋势判断（OI持续增长 vs 持续下降）
- **不计算百分比增长率**，只判断趋势方向

## 十一、注意事项

- 小币筛选器 = 5步完整筛选流程（扫描→排除→确认→入场→心法）

- OI 趋势需要7天预热（Phase 4），前7天只显示OI绝对值区间

- 做市商同秒异动需要秒级数据，无法在5分钟数据管道中实现
