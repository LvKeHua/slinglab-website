## 一、项目概览

筹码筛选器是一个纯前端+Cloudflare Worker 的实时加密货币合约筛选工具，涵盖从发现→排除→确认→入场→风控的完整流程。项目有三个核心视图（Tab），分别对应 @derrrrrrrq 方法论的不同层面：

| Tab | 名称 | 核心功能 | 方法论对应 |
|-----|------|----------|-----------|
| 🧲 | 筹码筛选 | 多交易所 24h 行情对比 | 基础数据面板（多源比价） |
| 👺 | 妖币扫描 | 成交量/OI 比挤压信号 | "oi和vol才是重点" + 挤压识别 |
| 🪙 | 小币筛选 | 5步完整筛选流程 + 9类信号标签 | 推文完整方法论（扫描→排除→确认→入场→风控） |

### 架构图

```
Windows 计划任务 (每15分钟)
  │
  ├─ relay.mjs ─→ Binance fAPI (proxy 127.0.0.1:7897)
  │                ├─ /fapi/v1/ticker/24hr        → 679 tickers
  │                ├─ /fapi/v1/openInterest        → 679 OI 值
  │                ├─ /fapi/v1/premiumIndex        → 批量资费率
  │                ├─ /fapi/v1/depth?limit=20      → Top 100 盘口深度
  │                ├─ /fapi/v1/exchangeInfo        → 合约上线日期
  │                ├─ Bybit + OKX tickers          → 857 tickers
  │                │
  │                ├─ POST /api/relay-tickers       (筹码数据)
  │                ├─ POST /api/relay-demon         (妖币数据)
  │                └─ POST /api/relay-coinfilter    (小币筛选数据)
  │
  ▼
Cloudflare Worker v10 (tokenomics-screener)
  │
  ├─ KV 存储 (TOKENOMICS_MARKET_DATA)
  │   ├─ exchange_proxy     → 1536 tickers (3 交易所)
  │   ├─ demon_data         → 679 coins (OI + 挤压信号)
  │   ├─ coinfilter_data    → 677 coins (全量信号标签)
  │   ├─ dashboard_html     → 前端页面 (96KB)
  │   └─ last_updated / count
  │
  ├─ GET /api/tickers       → 筹码筛选数据
  ├─ GET /api/demon         → 妖币扫描数据
  ├─ GET /api/coinfilter    → 小币筛选数据
  ├─ GET /api/status        → 状态汇总
  ├─ GET /                  → 前端 HTML (优先KV，降级inline)
  └─ Scheduled (hourly)     → 触发 KV 刷新
```

## 四、技术实现细节

### 数据管道

| 环节 | 实现 | 说明 |
|------|------|------|
| 数据抓取 | `relay.mjs` (Node.js) | 本地 Windows 计划任务每15分钟运行 |
| 代理 | HTTP CONNECT via 127.0.0.1:7897 | Binance/Bybit 在 Cloudflare Worker 边缘返回 403 |
| OI 抓取 | `/fapi/v1/openInterest` 逐合约 | 并发15，679个合约约50秒 |
| 资费率 | `/fapi/v1/premiumIndex` 批量 | 1次请求获取所有合约 |
| 盘口深度 | `/fapi/v1/depth?limit=20` Top 100 | 并发6 + 1次重试；全量679会触发418封禁 |
| 合约上线日期 | `/fapi/v1/exchangeInfo` 批量 | 1次请求 |
| 中继上传 | POST /api/relay-* | KV 写入，每日配额1000次 |
| KV 写入优化 | 3 key/cycle (tickers + demon + coinfilter) | 从8 key/cycle 合并，432次/日 |
| 前端交付 | 优先 KV → 降级 inline HTML (96KB) | 解决 KV 清空时冷启动问题 |

### 前端特性

| 特性 | 实现 |
|------|------|
| 框架 | 纯 CSS + vanilla JS，无 CDN |
| 散点图 | 自绘 HTML+CSS 气泡图，对数坐标 |
| 5步清单 | localStorage 持久化，三态循环 (✓/✕/空白) |
| 信号标签 | 纯客户端计算，9类自动标签 |
| 预设筛选 | 8个一键预设 + 6维手动筛选 |
| 排序 | vol/OI比、OI、涨跌幅、盘口深度 |
| 移动适配 | @media 768px 断点 |

### 关键配置

| 配置 | 值 | 说明 |
|------|-----|------|
| DEMON_MAX_SYMBOLS | 679 | Binance USDT 永续合约全量 |
| DEMON_MIN_VOL | 0 | 不过滤成交量 |
| OI_CONCURRENCY | 15 | OI抓取并发数 |
| DEPTH_CONCURRENCY | 6 | Depth抓取并发数（Top100） |
| DEMON_RELAY_KEY | 复用认证 | coinfilter 与 demon 共用 |
| 计划任务间隔 | 15分钟 | 减少Binance请求压力 |
| Binance IP封禁 | ~40分钟自动解封 | 679个OI请求不封禁，679个Depth必封 |

## 五、关键风险与偏差说明

| 风险/偏差 | 说明 |
|-----------|------|
| **盘口深度仅 Top 100** | 全量679个 depth 请求会触发 Binance HTTP 418 封禁约40分钟 |
| **OI 阶段是绝对值区间** | 他从未说"OI增长率"，只说"OI从低位开始增长"（定性）+ 绝对值区间 |
| **大后期阈值是推算** | 80M OI 阈值无精确原文，标注为"可能大后期派发" |
| **薄盘口阈值保守** | 他举例10万U，项目用20万U |
| **资费率不独立判断** | 他明确说"强控盘的中后期，资费在这里真的没啥用" |
| **KV 写入配额** | Cloudflare 免费版 1000次/日，当前约432次/日 |
| **数据延迟** | 15分钟更新周期，非实时 |
